## A third failure mode found on the way: a broken `cryptography`

`requirements.txt` warns that a missing dependency fails on `import
google.oauth2` and looks like a missing credential. A fresh container here has a
*third* failure mode that looks the same, and it survives
`pip install -r requirements.txt`:

After the requirements install, `totals --days 28` still did not reach the
credential check. It died at `scripts/gsc-query.py` line 47
(`from google.oauth2 import service_account`) with:

```
ModuleNotFoundError: No module named '_cffi_backend'
pyo3_runtime.PanicException: Python API call failed
```

Cause: the distro `cryptography` 41.0.7 at `/usr/lib/python3/dist-packages`
loads Rust bindings through cffi, and `cffi` is not installed in this image.
`google.auth.crypt.es` imports `cryptography.exceptions`, so the whole
credential path panics at import time.

Fix applied in this container to get a truthful answer: `pip install cffi`
(installed cffi 2.1.1, pycparser 3.0). After that the script reached its
credential check and reported the missing credential above.

This matters for diagnosis: the credential check at lines 50-60 sits *after*
the import at line 47, so on a fresh container this panic masks the credential
result entirely. `cffi` is not currently declared in `requirements.txt`.
