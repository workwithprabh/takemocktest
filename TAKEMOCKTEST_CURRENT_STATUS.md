Discovered a build-time gate `qa:questions` does not fully replicate: `src/lib/questions.ts` has a runtime validator (`if (text.has(question.question)) throw`) that requires every question's literal stem text to be unique *within a single test*, not just unique combined with its options — this only surfaces at `npm run build` time (via `next build`'s static generation), not at `qa:questions` time, because the full-mock test combines every question in the bank into one array. Reusing the same instruction stem across multiple items with different options/content (e.g. "Choose the sentence with correct subject-verb agreement." used for 4 different grammar items, "Choose the odd one out from the group." used for 5 different classification items — both patterns other banks in this corpus also use without issue at smaller counts) triggered a hard build failure the first time; fixed by varying the instruction phrasing naturally across repeated-template items ("Identify...", "Select...", "Pick...", "Find..."). This is now a standing rule for any bank with several items sharing a generic instruction stem: vary the wording, don't rely on options alone to differentiate them.
